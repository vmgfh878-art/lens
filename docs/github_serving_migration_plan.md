# 비공개 GitHub 릴리스 서빙 전환 진행표

기준일: 2026-09-30. R2 설계에서 비공개 GitHub 릴리스 방식으로 변경했다.

## 확정한 구조

- 로컬 PC: 원본 수집, 백필, 딥러닝 계산, 큰 데이터 보관을 계속 담당한다.
- 비공개 `vmgfh878-art/lens-serving`: 작은 서빙 결과만 릴리스 첨부파일로 전달한다.
- Render: 검증된 릴리스 파일을 캐시에 내려받아 API로 제공한다.
- Vercel: 기존 화면 배포를 유지한다.
- 코드 저장소: 배포 비상용 고정 폴백 한 벌만 보관한다. 매일 생성되는 데이터는 커밋하지 않는다.

PC가 꺼져 있어도 Render는 마지막으로 발행한 데이터를 제공한다. 새 수집·백필·계산은 PC가 켜져 실행될 때만 진행된다. Vercel이나 Render가 로컬 작업을 대신 수행하는 구조는 아니다.

## 발행·보관 계약

1. 로컬 파일 10개와 매니페스트를 검증한다.
2. 같은 PC의 중복 발행을 파일 잠금으로 막는다. 발행 PC는 한 대로 운영한다.
3. 불변 이름 `snapshot--스냅샷ID--파일명`으로 첨부파일을 올린다.
4. 모든 파일 크기와 해시를 검증한 뒤 릴리스 본문의 `latest`를 마지막에 교체한다.
5. 기존 `latest`를 `previous`로 보관한다. 같은 스냅샷 재발행은 이전 버전을 바꾸지 않는다.
6. 최신·이전 두 버전을 보호한 뒤 이 채널이 만든 나머지 첨부파일만 삭제한다.
7. 관리 토큰 방식이면 인증된 Render 동기화 API를 호출한다. 주기 동기화 방식이면 Render의 읽기 전용 준비 상태를 재조회한다. 어느 방식이든 활성 스냅샷 ID가 같은지 확인한다.

정상 종료 후 약 90MB 두 벌만 남는다. 최초에는 한 벌만 있다. 업로드 중 또는 실패 후에는 세 벌이나 불완전한 새 파일이 잠시 남을 수 있으며 다음 성공 발행에서 정리한다. 사용자 별도 첨부파일, Git 커밋과 태그는 정리 대상이 아니다. 삭제된 오래된 릴리스 파일은 GitHub에서 복구하는 보장이 없으며 필요한 보존은 로컬에서 담당한다.

발행 실패는 기존 최신 포인터를 유지한다. 다운로드·해시 검증 실패는 기존 활성 버전을 유지한다. Render 재시작 시 원격 접근도 실패하면 고정 폴백을 사용한다. 고정 폴백은 계속 최신으로 바꾸는 데이터가 아니므로 장기 장애 때 최신성 검사는 실패할 수 있다.

## 인증과 설정

로컬 발행은 현재 PC의 GitHub CLI 인증을 메모리에서만 읽어 사용한다. 토큰을 출력하거나 저장소에 넣지 않는다. CLI 인증을 사용할 수 없는 예약 작업 계정이라면 같은 사용자로 다시 인증하거나 별도 발행 토큰을 준비해야 한다.

Render에는 별도로 새 비공개 저장소만 선택한 세분화 개인 토큰이 필요하다. 저장소 권한은 `Contents: Read-only`이며 GitHub가 필수 `Metadata: Read-only`를 함께 부여했다. 읽기 클라이언트도 업로드·포인터 변경·삭제를 차단한다. 로컬 CLI의 넓은 발행 권한 토큰을 Render에 재사용하지 않는다. 토큰은 대화나 Git에 붙이지 않고 운영 서비스 `lens-backend-7stj`의 비밀 환경변수에 저장했다. 이 토큰은 **2026-10-30 만료**이므로 그 전에 교체해야 한다.

2026-09-30에 운영 Render에 `LENS_DATA_BACKEND`, 고정 폴백 경로, GitHub 저장소·태그·읽기 토큰과 `LENS_REMOTE_SYNC_INTERVAL_SECONDS=300`을 설정했다. 메인 코드 자동 배포 후 실제 활성화를 확인했다. 기존 CORS·Supabase 변수는 보존했으나 서빙 출처는 GitHub 릴리스가 우선한다.

```text
LENS_SERVING_STORAGE=github_release
LENS_GITHUB_REPOSITORY=vmgfh878-art/lens-serving
LENS_GITHUB_RELEASE_TAG=serving-snapshots
LENS_GITHUB_TOKEN=<Render 읽기 전용 비밀값>
```

일일 발행은 `--sync-mode periodic`을 사용한다. Render가 켜져 있는 동안 약 5분 간격으로 새 릴리스를 검증·활성화하며, 시작할 때도 검사한다. 발행기는 활성 스냅샷 ID가 같아질 때까지 준비 상태를 재조회한다. Render 수면·기동 또는 네트워크 지연이 있으면 5분보다 늦을 수 있다. `LENS_ADMIN_RELOAD_TOKEN`은 별도 수동 즉시 동기화 API를 사용할 때만 필요하며 읽기 토큰과 용도가 다르다. 기본 동기화 간격 0은 비활성이다. Render의 실제 환경변수와 `render.yaml`이 함께 일치해야 한다. GitHub 다운로드가 서명 URL로 이동할 때는 GitHub 인증 헤더를 넘기지 않는다.

실제 격리 검증에서 통신 라이브러리의 기본 요청 로그에 임시 서명 URL이 포함되는 문제를 발견했다. 배포 코드에서는 `httpx`·`httpcore`의 상세 로그를 비활성화하고 앱 자체의 동기화 상태·오류 로그만 남기도록 차단했다. DEBUG 설정에서도 이를 유지하는 회귀 테스트를 추가했다.

## 실행 명령

검증만 할 때는 인증과 네트워크 없이 실행한다.

```powershell
.\.venv\Scripts\python.exe backend\scripts\publish_serving_to_github.py --dry-run
```

정상 운영 발행은 파일 검증, 업로드, 보관 정리, Render 활성화 확인을 모두 포함한다. 로컬 관리 토큰이 있으면 기본값은 즉시 동기화이므로, 현재 주기 동기화 운영에서는 `--sync-mode periodic`을 명시한다. 윈도우 통합 작업에도 이 인자를 고정했다.

```powershell
.\.venv\Scripts\python.exe backend\scripts\publish_serving_to_github.py --sync-mode periodic
```

읽기 전용 품질 감사는 파일을 수정하거나 발행하지 않는다.

```powershell
.\.venv\Scripts\python.exe -B backend\scripts\audit_serving_snapshot.py --verify-remote-files
```

## 별도 윈도우 시작프로그램 점검

`LensDailyYFinance500LocalUpdate`는 예약 작업이 아니라 사용자 로그인 때 `scripts/run_lens_daily_yfinance_500_context_task.ps1`을 실행하는 시작프로그램이다. 일일 통합 작업의 7단계와 별개의 CP189 경로이며, CP186/187/187B 특징 파일을 갱신하도록 작성돼 있다. 2026-09-30 드라이런은 결과 저장 없이 Yahoo 조회를 실제 수행했고 503종목 중 498종목 성공, 5종목 실패였다. 기존 특징 파일의 최종 날짜는 모두 2026-05-08이며 실제 적용 실행의 최근 성공 증거가 없다. CP189의 `BLOCKED_YAHOO_429` 표시는 티커 결과 전체 문자열에서 `429`를 검색해 정상 처리 시간 `0.429`초에 반응한 오탐이다. 이 별도 경로를 다시 정기 운영할지, 중복 수집을 피하려고 중지할지는 사용자 판단이 필요하다. 본 서빙 전환의 7단계 계산 결과와 혼동하지 않는다.

주간 감사 모델 `gpt-5.5`는 현재 설정을 유지했다. [OpenAI 공식 예약 작업 문서](https://learn.chatgpt.com/docs/automations?surface=app)는 2026-10-14 모델 종료를 안내하므로 그 전에 사용자 판단으로 모델을 교체해야 한다. 이번 서빙 전환과 별도의 판단이다.

기존 약 4GB Git 이력은 이번 전환으로 사라지지 않는다. 과거 이력 재작성·강제 푸시는 별도 사용자 판단 없이는 하지 않는다. R2 계정과 과금 설정은 만들지 않았으며 Render·Vercel·GitHub 자체의 이용 제한이나 장애가 없어지는 것은 아니다.
