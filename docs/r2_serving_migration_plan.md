# R2 서빙 전환 진행표

이 문서는 과거 R2 설계의 구현 기록이다. 2026-09-29 사용자 결정으로 비공개 GitHub 릴리스 방식으로 변경했다. 현재 진행 상태와 남은 운영 작업은 [GitHub 서빙 전환 진행표](github_serving_migration_plan.md)를 따른다. R2 계정이나 과금 설정은 만들지 않는다.

기준일: 2026-09-26

## 상태 정의

- `구현 완료`: 격리 브랜치에서 코드와 자동 테스트까지 완료했다.
- `운영 완료`: 실제 계정 설정, 업로드, 배포, 장애 전환 확인까지 완료했다.
- 현재 1~9단계의 코드 변경은 메인 브랜치나 운영 환경에 반영되지 않았다. 코덱스 주간 감사의 검사 기준만 실제 예약 설정에 갱신했다.

## 완료한 구현

1. 기준선 기록: Git 데이터 이력과 현재 서빙 묶음 크기를 측정했다.
2. 경로 분리: 로컬 생성 경로, 고정 폴백 경로, 런타임 R2 캐시 경로를 분리했다.
3. 무결성 계약: 필수 파일 10개, 크기, SHA-256, 콘텐츠 지문을 매니페스트로 고정했다.
4. 비공개 R2 발행: 버전 디렉터리를 올린 뒤 `latest.json`을 마지막에 교체하도록 구현했다.
5. Render 동기화: 임시 경로에 내려받아 검증한 뒤 완성 버전만 원자적으로 활성화한다.
6. 준비 상태: R2와 로컬 서빙 경로를 Supabase보다 우선하고 상태를 노출한다.
7. 일일 발행 전환: 윈도우 통합 파이프라인에서 일일 Git 데이터 커밋과 Supabase 발행을 제거하고 R2 발행·Render 동기화로 바꿨다.
8. 고정 Git 폴백: 현재 검증된 45MB 서빙 묶음 한 벌만 `backend/data/bootstrap/v1`에 고정하고, 매일 생성되는 `backend/data/v1`은 Git에서 제외한다.
9. 품질 감사·Slack 판정: 로컬 파일, 고정 폴백, R2 원격 파일 해시, Render의 실제 서빙 출처·버전·최신성을 검사한다. 일일 발행이 실패해도 배포 검수를 수행하고 폴백 응답과 서비스 실패를 나눠 알린다.

8단계 검증: 백엔드 테스트 233개 통과, 기존 제외 7개, 응답 스냅샷 9개 통과. 실제 폴백 파일 10개의 SHA-256이 기준선과 일치했다. R2 실패 시 검증된 폴백을 유지하고 준비 상태를 `degraded`로 알리는 테스트가 통과했다. 기존 CP175 연구용 백업은 디스크에 보존하고 Git 추적만 해제했다.

9단계 검증: 백엔드 테스트 248개 통과, 기존 제외 7개, 응답 스냅샷 9개 통과. 실제 고정 파일로 부팅하면서 R2 장애를 흉내 내 가격·라인·밴드 응답과 폴백 경고 판정까지 확인했다. 원격 파일 손상, 버전 불일치, 오래된 가격·예측, 폴백 손상, 발행 후 Render 동기화 실패를 검사했다. PowerShell 5.1 구문 및 알림 색상 판정도 통과했다. Windows와 Linux에서 같은 파일 바이트가 배포되도록 고정 폴백에 Git 줄바꿈 변환을 끄고 Git 객체 해시를 대조했다.

## 아직 하지 않은 운영 작업

1. 비공개 R2 버킷을 만들고 로컬 쓰기 키와 Render 읽기 키를 분리한다.
2. 로컬과 Render에 R2 및 관리자 토큰 환경변수를 넣는다.
3. 최초 스냅샷을 실제 R2에 올리고 Render가 같은 스냅샷 ID를 활성화하는지 확인한다.
4. R2 정상, R2 장애 후 고정 폴백, 고정 폴백 손상 세 경우를 실제 배포에서 시험한다.
5. 격리 브랜치를 메인에 병합하고 GitHub에 푸시해 Render를 배포한다.
6. 전환 후 기존 Git 데이터 발행 스크립트를 제거한다.
7. R2 보관 개수와 삭제 정책을 결정하고 구현한다.
8. 기존 약 4GB Git 이력을 재작성할지 별도로 판단한다. 이 작업은 파괴적이므로 운영 전환과 분리한다.

## 갱신한 감사·알림 논리

### 코덱스 데이터 품질 감사

- 현재 활성 상태인 `Lens 주간 통합 리스크·품질 감사`의 예약 설정을 새 구조에 맞춰 갱신했다. 일요일 09:30, 기존 모델·프로젝트·활성 상태는 유지했다.
- Git 데이터 커밋 최신성이나 Supabase 서빙 최신성을 정상 기준으로 사용하지 않는다.
- 로컬 생성 데이터 품질, 스냅샷 매니페스트와 파일 해시, R2 `latest`가 가리키는 스냅샷, Render 활성 스냅샷 ID를 순서대로 읽기 전용 검증한다.
- Render가 `source=r2`인지 `source=bootstrap`인지 구분하고, 폴백 중이면 원인과 마지막 R2 성공 시각을 경고한다.
- 중지된 기존 `Lens 데이터 품질 감사`는 중복 실행하지 않고 그대로 둔다.

### Slack 발행·폴백 알림

- 정상: R2 발행 스냅샷 ID와 Render 활성 스냅샷 ID가 같으면 성공으로 알린다.
- 경고: Render는 응답하지만 `source=bootstrap`이면 폴백 작동, R2 오류, 폴백 스냅샷 ID를 구분해 알린다.
- 실패: 필수 파일 또는 폴백 해시 검증 실패, 응답 불가, 스냅샷 불일치는 실패로 알린다.
- 발행 실패 때도 배포 검수를 실행하도록 연결했고 위 상태별 색상 판정을 로컬에서 확인했다.
- 실제 R2 연결, 장애 시험 및 Slack 메시지 수신은 아직 미검증이다.

검사 기준 원문은 `docs/r2_data_quality_audit_prompt.md`에 보관한다. 예약 감사는 메인에 새 코드가 아직 없으면 전환 미완료로 표시하고 현재 운영 경로를 검사한다. 새 읽기 전용 진입점은 `backend/scripts/audit_serving_snapshot.py`이며 `--verify-r2-files`로 원격 파일을 디스크에 쓰지 않고 메모리에서 해시 검사한다.

## 별도 로컬 작업 주의

`scripts/cp189_daily_yfinance_500_context_pipeline.py`는 현재 `scripts/cp*.py` 무시 규칙에 걸린 로컬 전용 파일이다. 윈도우 예약 작업에서는 실행할 수 있지만 이 브랜치나 새 클론에는 자동으로 포함되지 않는다. 코덱스 주간 감사와는 별개의 수집·검증 파이프라인이다.
